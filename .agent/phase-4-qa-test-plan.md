## Key Interactions to Verify

### Snake movement
- Snake moves in the queued direction each tick
- 180° reversal (opposite direction) is silently blocked; snake continues current direction
- Snake starts with 3 segments at (10,9),(9,9),(8,9) moving RIGHT
- After `grow()` + `move()`: snake gains 1 segment; tail NOT removed

### Collision detection
- Moving into a wall (x<0, x>=20, y<0, y>=20) triggers GAME_OVER
- Moving the head onto any body segment (not the head itself) triggers GAME_OVER
- Valid moves inside the board with no self-collision do NOT trigger GAME_OVER

### Food logic
- Food spawns at a position not occupied by the snake
- When snake head reaches food position: snake grows, food respawns, `foodEaten` event fires
- `foodEaten` fires exactly once per food eaten (not on normal moves)
- Food respawn never overlaps snake segments (fuzz-testable)

### Game orchestration
- `update()` is a no-op when state is not PLAYING
- `queueDirection()` sets pending direction; consumed on next `update()` then cleared
- After `restartGame()`: snake is back to 3 segments at initial position; food is valid; state is IDLE

## Edge Cases

- 180° reversal in all 4 directions (RIGHT→LEFT, LEFT→RIGHT, UP→DOWN, DOWN→UP)
- `grow()` called twice before a `move()` — only 1 segment added (boolean flag, not counter)
- Food respawn when board is nearly full (399/400 cells occupied) — must find the 1 free cell
- Full board (400/400 cells occupied) — `respawn()` returns false, game does not crash
- Wall collision on all 4 edges (not just x=20)
- Self-collision: head does NOT collide with itself (would break every move)
- `restartGame()` only valid from GAME_OVER state; IDLE/PLAYING/PAUSED calls are no-ops (existing behavior)

## Critical Paths

1. Game start → 3 moves right → no collision → state stays PLAYING
2. Game start → move right → food at (11,9) via deterministic RNG → snake grows to 4 → food respawns elsewhere
3. Game start → walk snake into right wall → GAME_OVER event fires
4. Game start → grow snake 4 times → steer into own body → GAME_OVER event fires
5. GAME_OVER → restartGame() → startGame() → update() works cleanly
