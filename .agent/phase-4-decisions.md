## D-01: Board.checkCollision() signature

```
DECISION: Board.checkCollision(pos: Vector2, snake: Snake): boolean
CONTEXT: Phase spec deliverables say "checkCollision(pos, snake)" but acceptance criteria
         say "checkCollision(pos)" — contradiction to resolve before sub-agents implement.
OPTIONS:
  A) checkCollision(pos) — Board only knows walls; caller handles self-collision
  B) checkCollision(pos, snake) — Board centralises all collision logic (wall + self)
  C) Two methods: checkWallCollision(pos) + checkSelfCollision(pos, snake)
CHOICE: B
REASONING: One boolean gate in update() is cleaner than two. Matches architecture doc
           data flow. Option A leaks self-collision responsibility to GameManager.
           Option C is unnecessary abstraction (always called together). Completeness wins.
CONFIDENCE: HIGH
```

## D-02: Self-collision check skips head (critical correctness issue)

```
DECISION: checkCollision skips segments[0] (current head) for self-collision
CONTEXT: move() prepends new head to segments[]. If checkCollision checks pos against
         all segments including segments[0], and pos === snake.head === segments[0],
         the check always returns true — every move would end the game. This was
         identified by the outside voice as a critical bug.
OPTIONS:
  A) Pass new head before inserting it; move() becomes two-phase commit
  B) checkCollision(pos, snake) skips segments[0] for self-collision check
  C) checkCollision receives snake.segments.slice(1) from caller
CHOICE: B — checkCollision skips segments[0] internally, documented with a comment
REASONING: Option A restructures move() significantly. Option C leaks internals
           to GameManager. Option B is cleanest public API. Document the skip rule
           clearly in Board.ts comment.
CONFIDENCE: HIGH
```

## D-09: Food.respawn() algorithm — build available[] array

```
DECISION: respawn() builds available[] of unoccupied cells, picks random index
CONTEXT: Need random unoccupied cell. Two algorithmic options.
OPTIONS:
  A) Rejection sampling — pick random cell, retry if occupied (risk: near-infinite loop near full)
  B) Build available[] then pick index — O(n) time+space, guaranteed O(1) final pick
CHOICE: B
REASONING: 400 cells max; O(400) space is trivial. Rejection sampling risks near-infinite loop
           when board is 90%+ full (increasingly likely late game). "Handling more edge cases,
           not fewer." Returns false if available.length === 0 (board full = win stub).
CONFIDENCE: HIGH
```
